# PohuismAndroid

Android-приложение на Kotlin и XML (без Jetpack Compose).

## Что уже есть в приложении

- Полноэкранный режим.
- Список четырёх демонстрационных контактов с аватарками.
- Отдельный экран чата и встроенная экранная клавиатура RU/EN.
- GitHub Actions собирает тестовый APK при push в `main`.

## Состояние сетевой части

Добавлена **серверная основа** на Firebase, но Android-экран пока не подключён к ней: текущий APK всё ещё использует демонстрационные контакты и локальный ответ. Не считай чат работающим через интернет, пока не создан Firebase-проект, не настроена Android-конфигурация и не выполнена интеграция клиента.

В репозитории теперь есть:

- `functions/src/index.ts` — доверенные серверные функции.
- `firestore.rules` — закрытые по умолчанию правила доступа.
- `firebase.json` — конфигурация Firebase CLI.

### Выбранная схема сети

1. **Вход:** Firebase Authentication с SMS-кодом; сетевые функции доступны только аккаунтам с подтверждённым номером.
2. **Поиск по номеру:** сервер ищет один номер в Firebase Auth. Номера телефонов не дублируются в Firestore, а клиент не получает список пользователей.
3. **Добавление контакта:** сервер создаёт заявку; только получатель может принять или отклонить её.
4. **Чат:** после принятия заявки сервер создаёт дружбу и приватный чат.
5. **Кнопка:** приложение передаёт ID чата, а сервер сам создаёт сообщение `Иди нахуй`. Произвольный текст через эту функцию отправить нельзя.
6. **Защита:** Firestore-клиенты не могут сами создавать заявки, переписки или сообщения; поиск по номеру и отправка сообщений ограничены по частоте.

Перед публичным запуском нужно дополнительно включить Firebase App Check, проверить правила в Emulator Suite и добавить возможность блокировки пользователя/жалобы. Сейчас это не production-ready сервис: серверная основа создана, но ещё не развёрнута и не проверена на настоящем Firebase-проекте.

### Почему пока нет файла `google-services.json`

Он относится к конкретному Firebase-проекту и не может быть придуман заранее. Когда выберем и создадим проект, Android-приложение нужно зарегистрировать с package name `com.example.pohuism`, скачать файл из Firebase Console и подключить Android SDK. До этого я намеренно не добавлял фиктивные настройки и не менял клиентский код так, чтобы приложение запускалось с заведомо нерабочей сетью.

### Развёртывание backend

Для реального запуска потребуется Firebase-проект с Authentication (Phone), Cloud Firestore и Cloud Functions. Развёртывание Cloud Functions требует плана Blaze с привязанным платёжным аккаунтом; перед этим настрой бюджетные уведомления и не включай биллинг без согласования с владельцем платёжного аккаунта. Для разработки сначала можно использовать Firebase Emulator Suite.

Когда Firebase-проект будет готов:

```bash
npm --prefix functions install
npm --prefix functions run build
firebase login
firebase use --add
firebase deploy --only firestore:rules,functions
```

Эти команды только описывают шаги — я не запускал deploy и не подключал платёжный аккаунт.

## Получение APK

1. Открой [GitHub Actions](https://github.com/HelterFall/PohuismAndroid/actions).
2. Выбери успешный запуск **Build Android APK**.
3. Скачай артефакт **Pohuism-debug-apk** и распакуй ZIP.

## Технологии

Kotlin, Android Activity, XML layouts, RecyclerView, AndroidX Core, Firebase Admin SDK и Cloud Functions (серверная основа).
